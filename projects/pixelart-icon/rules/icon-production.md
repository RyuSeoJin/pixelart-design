# 픽셀 아트 아이콘 제작 규칙

아이콘 크기의 정본은 `../spec/design/pixel-spec-icon.json`입니다. 이 프로젝트는 UI용 아이콘을
제작하며, 캐릭터의 6등신 비율·얼굴 보정·320px 출력 규칙을 적용하지 않습니다.

## 제작 순서

1. 아이콘의 용도와 대상을 정하고, 같은 계열에 사용할 팔레트·외곽선·여백을 시안에서 확인합니다.
2. `source/`에 참고와 작업 자료를, `sprites/`에 편집 가능한 원본을 보존합니다. 남의 이미지를
   재배포 자료로 넣지 않습니다. 사물·메뉴의 실제 도트 작업 격자는 16×16입니다. 기호는 도형 원본을 사용합니다.
3. 사물·메뉴는 16×16 작업본을 최근접 보간으로 1·2·3·4배 출력합니다. 기호는 도형 원본에서 16·32·48·64px를 각각 직접 출력합니다. `export/{이름}/`에
   `icon-16.png`, `icon-32.png`, `icon-48.png`, `icon-64.png`를 둡니다.
4. 출력 뒤 별도로 1px 세부 묘사를 추가하지 않습니다. 사물·메뉴 수정은 16×16 원본에, 기호 수정은 도형 원본에 반영하고 모두 다시 출력합니다.
5. 네 크기에서 형태의 식별성과 실제 투명 배경을 확인합니다. 사물·메뉴 확대본은 16px 원본의 최근접 확대와
   RGBA가 같아야 합니다. 기호는 크기별 직접 출력이므로 이 일치 조건을 적용하지 않습니다. 반투명 가장자리와 흐림을 허용하지 않습니다.
6. 사용자 승인과 검수가 끝나면 `releases/`에 승인 근거·검수 결과·파일 해시를 기록합니다.
   저장소 루트 `RESOURCE_WORKFLOW.md`의 등록 절차로 공용 `resources/`에 등록합니다.

## 크기와 색상

| UI 배율 | 제공 크기 | 도트 원본 대비 확대 |
|---|---|---|
| 50% | 16×16 | 1배 |
| 100% | **32×32 기본** | 2배 |
| 150% | 48×48 | 3배 |
| 200% | 64×64 | 4배 |

마지막 열은 사물·메뉴에 적용합니다. 기호는 같은 제공 크기로 도형을 직접 출력합니다.

가시 픽셀은 RGB 각 채널을 10 이상으로 사용합니다. `#000000`을 사용하지 않고,
투명도는 알파 0 또는 255로 표현합니다. 완전 투명 픽셀의 RGB는 색상 하한 검사에서 제외합니다.
사물 아이콘은 대표 v1의 표현 밀도를 기준으로 사용합니다. 메뉴·기호는 이번 유색 v2와 도형 방식으로 수정했으며 외형은 재검토합니다. 개별 사물의 새 팔레트와 외형도 전체 검토에서 확인합니다.

이 배율 표는 32px 기본 표시 크기에 대한 관계입니다. 사용하는 UI에서도 최근접 표시와 화면의
픽셀 정렬을 유지해야 합니다. 화면 배율 때문에 다시 소수배로 리샘플링하면 도트가 고르지 않을 수 있습니다.

공용 등록 도구는 크기·알파·색상·해시를 검사합니다. 네 출력의 최근접 일치와 디자인 적합성은
프로젝트 검수에서 별도로 확인하고 등록서의 `project_spec`에 근거를 남깁니다.

## RecordTales 제작 범위와 승인 순서

목록 정본은 `../spec/design/recordtales-icon-catalog.json`입니다. 메뉴 9·기호 14·분류 10·티켓 5·감정 2·주문 12·행동 14, 총 66종입니다.
전체 66종은 색을 포함한 PNG로 제공합니다. 메뉴 9종은 사물에 맞는 색과 명암을, 기호 14종은 의미별 색과 일정한 외곽선을 사용합니다. 기본 사용 시 런타임 색상 곱은 흰색으로 두어 원래 색을 보존합니다.

대표 6종은 cmd_settings, sym_close, icon_book, tpl_idea, order_restaurant, act_cook입니다.
여섯 시안을 네 크기와 밝고 어두운 배경에서 확인한 뒤 외곽선·색·여백·표현 밀도를 승인받습니다.
고해상도 생성 결과는 구상 자료이며 실제 16px 원본과 구분합니다. 생성 원본·요청문·16px 정리 절차를 보존합니다.
대표 6종 v1은 사용자 승인한 스타일 기준입니다. 원본 격자에서 사방 1px 이상 투명 여백을 유지하고, 유색 아이콘은 대표 시안의 짙은 윤곽과 제한된 명암을 따릅니다. 승인 근거와 파일 해시는 source/production-v1/representative-approval.json에 보존합니다.

대표 시안 승인 후 메뉴 9종 → 기호 14종 → 분류·티켓 15종 → 감정·주문·행동 28종으로 제작합니다.
대표 시안은 이 수량에 포함합니다. 이미 만든 대표 아이콘을 다시 별도 수량으로 더하지 않습니다.
검토본은 `export/{이름}/vN/`에 네 출력으로 보존하며 승인 전 공용 resources에 등록하지 않습니다.

## 공통 UI 형태 기준

이 절은 이후 제작·수정하는 모든 아이콘에 적용합니다. 그림을 시작할 때 제작 목록에 대칭 방식, 중심축과 좌표계, 얼굴 영역, 각도 조건을 기록합니다. 비대칭 구성에는 이유도 기록합니다. 수치 정본은 `pixel-spec-icon.json`의 `ui_geometry`입니다.

### 시점과 재질 식별

작은 화면에서도 사물의 작동 방향과 연결 구조가 읽히도록 **2D 사이드뷰(옆에서 본 평면 형태)**를 기본으로 합니다. 원근 때문에 자루가 짧아지거나 날이 비틀려 보이는 구성은 피합니다. 도끼·곡괭이는 날의 넓은 옆면과 자루의 연결이 보이게 배치하고, 그루터기도 같은 시점의 앞면으로 표현합니다.

사이드뷰보다 대상을 더 직관적으로 알아볼 수 있으면 다른 시점을 사용합니다. 예를 들어 ORDER_RESTAURANT는 접시와 음식의 내용이 읽히는 위쪽 시점을 사용할 수 있습니다. 인물·얼굴·기호도 의미 전달에 유리한 정면을 허용합니다. 제작 목록의 `viewpoint`에 시점과 선택 이유를 기록하며, 한 물체의 연결된 부품에 서로 다른 원근을 섞지 않습니다.

곡괭이 양 날에는 외곽선 안쪽의 금속색 면을 남깁니다. 끝의 마지막 한 픽셀은 외곽선일 수 있지만, 양쪽 날 전체가 외곽선만으로 보이면 폭이나 배치를 다시 설계합니다. 양끝은 같은 길이와 테이퍼(끝으로 갈수록 좁아지는 형태)를 사용합니다. 도끼·곡괭이의 결합부 밖으로 나온 나무 자루 끝은 기존 자루와 같은 축에 놓습니다. 철날 자체를 나무색으로 칠하지 않습니다.

이 기준은 이후 제작·수정에 적용합니다. 기존 파일은 개별 검수 전 자동 통과시키지 않습니다. 시점 선택은 사용자 외형 승인과 구분해 기록합니다.

### 중심축과 대칭

정면 인물, 정면 사물, 기계 및 기호는 좌우 대칭을 기본으로 설계합니다. 먼저 중심축을 정하고 한쪽을 반사해 다른 쪽을 만듭니다. 외곽뿐 아니라 목·어깨·손잡이·구멍 등 주요 구조의 중심도 맞춥니다. 명암이나 재질의 빛 방향은 외곽 대칭과 별도로 판정합니다.

정수 픽셀의 중심축과 두 픽셀 사이의 중심축을 구분합니다. 홀수 폭은 가운데 한 픽셀, 짝수 폭은 가운데 두 픽셀 사이를 축으로 삼습니다. 대칭을 맞추려고 한쪽만 늘리거나 가로·세로 비율을 따로 조정하지 않습니다.

### 인물 얼굴

인물 얼굴과 감정 얼굴은 작업 원본에서 5·7·9·13px처럼 홀수 폭을 사용합니다. 둥근 얼굴의 가로·세로 지름은 같게 두고, 원형 도트 마스크의 좌우와 위아래를 반사해 확인합니다. 눈은 축 양쪽에 같은 간격으로, 코·입의 중심은 같은 축에 놓습니다. 인물의 머리·목·어깨도 축을 공유합니다. 표정에 필요한 비대칭은 이유를 기록합니다.

16px처럼 짝수 캔버스에 홀수 얼굴을 넣으면 좌우 바깥 여백이 1px 다를 수 있습니다. 이 경우 얼굴 자체의 대칭을 우선합니다. 홀수 조건은 원본 격자 기준이며 2배 확대에서 7px가 14px가 되는 것은 정상입니다. 확대 후 홀수로 되돌리려고 픽셀을 추가하지 않습니다.

### 직선과 각도

수평은 0도, 수직은 90도, 대각선은 45도를 기본으로 사용합니다. 45도 선은 가로와 세로 이동량의 절댓값이 같습니다. 망치는 수평 머리와 수직 손잡이를 기본으로 하고 두 축은 90도로 만납니다. 복합 아이콘에서도 망치 자체를 임의로 기울이지 않습니다.

꺾쇠형 방향 기호는 두 45도 사선이 정확히 90도로 만나게 만듭니다. 방향 삼각형도 진행 방향의 꼭짓점을 90도로 맞춥니다. 다른 방향은 같은 원본의 90도 회전 또는 반사로 생성하며, 방향마다 따로 그리지 않습니다. 체크는 의미상 비대칭인 두 팔을 유지하고 X는 중심 대칭과 같은 획 두께를 유지합니다.

### 부품 연결과 축 연속성

길쭉한 부품이 휘어 보이지 않도록 먼저 손잡이·막대·날의 중심선을 정하고, 부품을 그 선에 맞춰 배치합니다. 외곽만 직선이어도 연결 위치가 어긋나면 통과시키지 않습니다. 수치와 기록 항목은 `pixel-spec-icon.json`의 `ui_geometry.rigid_alignment`을 따릅니다.

1. **기준축:** 원본 좌표에 시작점·결합점·끝점을 기록합니다. 직선 부품은 0·45·90도 중 하나의 축을 사용하고, 세 점이 한 직선에 있어야 합니다. 끝의 장식이나 돌출부만 따로 옮기지 않습니다.
2. **가려진 구간:** 도끼 머리·손잡이 감개·다른 물체에 가려져도 중심선은 이어집니다. 머리 반대쪽에 노출되는 나무 끝은 손잡이 중심선의 연장선에 놓습니다. 조정이 필요하면 연결된 부품을 함께 다시 배치합니다.
3. **두께와 계단:** 직선 구간은 축에 수직인 방향의 두께를 일정하게 유지합니다. 45도는 가로 1·세로 1 이동을 반복하고, 중간에 1:2 또는 2:1 계단을 섞지 않습니다. 굵기가 달라지는 손잡이 끝·날의 테이퍼는 시작 위치와 이유를 기록합니다.
4. **접합:** 망치의 머리 중심과 손잡이 축은 직각으로 만납니다. 한쪽 날 도끼는 전체 좌우 대칭을 강제하지 않지만, 자루가 통과하는 결합부와 돌출 끝의 축은 일치해야 합니다. 검·연필은 손잡이·몸통·끝을 같은 축에 둡니다.
5. **구조와 명암:** 나무색이나 금속 하이라이트도 부품의 방향을 따릅니다. 접합부에서 색 띠가 갑자기 옆으로 뛰어 꺾인 것처럼 보이지 않게 합니다. 색을 빼고 실루엣만 보는 검사와 중심선 표시 검사를 함께 합니다.
6. **의도된 곡선:** 낚싯줄·고리·곡괭이 날처럼 기능상 휘는 부분은 부품별 예외로 기록합니다. 손잡이까지 같이 휘게 만들지 않습니다. 도끼가 나무에 박힌 경우에는 절삭 날이 나무 표면 안으로 들어가고 앞쪽 나무가 일부를 가려야 합니다.
7. **검수:** 축을 표시한 검토판에서 결합점과 끝점의 정렬을 확인하고, 16·32·48·64px 실제 출력에서 꺾임·두께 변화·물체 식별성을 확인합니다. 위치 수정 후에는 연결 부품 전체를 다시 검수합니다.

### 의미상 필요한 비대칭

책의 옆면, 한 방향을 향하는 신발·도구, 체크의 짧고 긴 팔, 집과 망치의 겹침처럼 비대칭이 의미를 전달할 때만 예외로 둡니다. 제작 목록에 사유와 각 구성요소의 축을 기록합니다. 기존 그림이 비대칭이라는 사실만으로 예외를 자동 인정하지 않습니다.

### 제작과 검수 순서

1. 용도·표시 크기와 대칭 가능 여부를 정하고 축·얼굴 지름·각도·예외 사유를 기록합니다.
2. 색을 넣기 전에 실루엣을 만들고 반사·회전으로 구조를 확인합니다.
3. 얼굴·몸·도구의 축을 맞춘 뒤 색과 명암을 넣습니다. 얼굴을 가로 또는 세로로만 리사이즈하지 않습니다.
4. 원본과 네 출력에서 반사 일치, 얼굴 홀수 지름, 화살표 직각, 획 두께 및 가독성을 검사합니다. 기호는 크기별 직접 출력, 사물·메뉴는 최근접 확대라는 기존 구분을 유지합니다.
5. 검사 결과와 외형 승인 상태를 분리해 기록합니다. 이전 아이콘은 새 규칙이 생겼다는 이유만으로 통과 처리하지 않고 개별 검수 상태를 남깁니다.

## 공통 외곽선 기준

아이콘마다 테두리의 인상이 달라지지 않도록 모든 계열은 아래 기준을 사용합니다. 수치 정본은 `pixel-spec-icon.json`의 `outline`입니다.

- **색상:** 기본 외곽선은 `#342D46`, 알파는 255입니다. 밝은 배경과 어두운 배경에서 모두 확인합니다. 재질별 명암은 내부 면에 넣고 외곽선을 밝게 지우지 않습니다. 다른 색이 필요한 경우 목록에 색과 이유를 기록합니다.
- **픽셀 원본 두께:** 16px 원본에서 수평·수직 외곽선은 1px입니다. 최근접 출력의 두께는 16·32·48·64px에서 각각 1·2·3·4px입니다. 모서리의 계단 픽셀을 선이 굵어진 것으로 오해해 깎지 않습니다.
- **도형 원본 두께:** 기존 기호의 32px 기준 1.8px를 유지합니다. 네 크기에서 0.9·1.8·2.7·3.6px로 비례 계산해 직접 출력합니다. 이 값은 도형 중심선 기준 폭이며 실제 가장자리의 픽셀 개수와 같지 않습니다. 두 제작 방식의 숫자를 억지로 일치시키지 않고 같은 화면 크기에서 시각적 두께를 검수합니다.
- **연속성:** 닫힌 물체의 외곽은 끊김 없이 둘러쌉니다. 계단 대각선의 모서리 접촉은 허용하지만 의도하지 않은 투명 틈, 빠진 테두리, 떠 있는 픽셀은 제거합니다. 화살표 등의 열린 형태는 의도된 구조로 기록합니다.
- **연결과 겹침:** 같은 물체의 두 부분이 닿으면 공통 경계 한 줄을 공유합니다. 양쪽 외곽선을 겹쳐 두꺼운 검은 띠를 만들지 않습니다. 집과 망치처럼 별개 물체가 겹치면 전경의 외곽선을 남기고 뒤쪽의 가려진 선을 없앱니다.
- **주요 오브젝트별 처리:** 도끼와 그루터기처럼 각각 식별되어야 하는 대상은 합성 전에 개별 외곽선을 만듭니다. 전체를 합친 실루엣에만 외곽선을 넣어 접촉 경계를 지우지 않습니다. 뒤쪽 대상 → 앞쪽 대상 순서로 배치하고, 접점에서는 앞쪽 대상의 1px 외곽선 한 줄을 남깁니다. 완전히 가려진 뒤쪽 선은 표시하지 않습니다. 같은 물체의 미세한 명암까지 각각 둘러싸지는 않습니다.
- **겹침 검수:** 배경과 맞닿은 바깥 윤곽뿐 아니라 주요 대상 사이의 접촉 경계도 16px 원본과 네 출력에서 확인합니다. 도끼날과 그루터기가 한 면으로 합쳐 보이거나 경계가 이중으로 굵어지면 재작업합니다. 매입된 날은 나무 앞면이 일부를 가린 상태에서도 남은 금속 면과 나무의 경계가 읽혀야 합니다.
- **인물 접합:** ROSTER는 둥근 머리의 크기와 중심축을 유지하며 머리 하단과 몸 상단을 붙입니다. 길게 드러난 목이나 투명 간격을 두지 않습니다. 다른 인물도 목 때문에 분리돼 보이지 않도록 연결을 검수합니다.
- **내부 선과 검수:** 내부 구분선은 외곽선보다 굵게 만들지 않습니다. 원본과 네 출력에서 색·두께·좌우 대칭·접합부·투명 틈을 확인합니다. 기존 아이콘의 통과 여부는 별도 기록하며 예외에는 이유와 부위를 남깁니다.

## 메뉴의 형태와 겹침

메뉴는 수평·수직 면과 일정한 계단 대각선을 기본으로 구성합니다. 톱니바퀴처럼 기계적인 형태는 곧은 톱니와 좌우·상하 대칭을 유지합니다. 작은 곡률을 잘게 나누기보다 읽히는 면과 모서리를 먼저 정합니다.

도구와 사물은 의미가 명확하도록 겹쳐 배치할 수 있습니다. EDIT는 집을 뒤에, 망치를 앞에 두고 짙은 외곽선으로 두 형태를 구분합니다. RECRUIT는 인물 정보가 있는 서류, ROSTER는 한 명의 인물로 표현합니다.

## 기호 도형 제작

체크·X·이동 화살표·재생·정지·접기·펼치기·별·수정 기호는 32×32 좌표계의 도형 원본으로 설계합니다. 체크는 짧은 왼쪽 획과 긴 오른쪽 획, X는 중심과 양팔의 대칭을 유지합니다. 원본 외곽선은 32px 기준 1.8px이며 각 크기에서 비례 적용합니다.

16px 확대의 불규칙한 모양을 피하려고 네 크기를 도형에서 직접 출력합니다. PNG 가장자리는 알파 0/255로 유지합니다. SVG 편집 화면의 가장자리 처리는 뷰어마다 다를 수 있으므로 게임 검수 기준은 출력 PNG입니다. 예시 이미지는 형태 참고이며 복제하지 않습니다. 현재 원본 경로는 아이콘 목록의 geometry_file과 editable_file을 따릅니다. 도형 좌표와 SVG는 해당 버전의 source 폴더에 보존합니다.

## 화면 표시와 UE 연결

기본 UI 배율에서 작은 기호도 32×32px 아이콘 영역을 사용합니다. 버튼·목록 행 높이·글자 간격은 이 영역에 맞춰 별도 조정합니다.
50·100·150·200%에서 각각 16·32·48·64px 파일을 같은 화면 픽셀 크기로 표시합니다. 25%와 임의 중간 배율은 이번 보장 범위에서 제외합니다.
운영체제 DPI와 UI 배율이 겹쳐 소수 배율이 되지 않게 최종 화면 픽셀을 검수합니다. 그림 내부 여백과 UI 배치 여백을 구분합니다.

현재 UE는 Content/Slate/Icons의 고정 이름을 읽으며 SVG가 PNG보다 우선합니다. 크기별 파일 자동 선택은 아직 구현되지 않았습니다.
공용 resources의 크기별 파일을 UE에 전달하는 방법, 배율별 파일 선택, 최근접 필터와 픽셀 정렬, 버튼·목록 배치 변경은 후속 연결 작업입니다.
cmd_guide는 UI가 요청하지만 등록 목록에 없어 코드 등록이 필요합니다. 지금 파일 제작만으로 UE 연결을 완료한 것으로 보지 않습니다.
player_crest·bld_guild·estate_floor·캐릭터 초상화는 후속 별도 리소스이며 이번 66종에 포함하지 않습니다.

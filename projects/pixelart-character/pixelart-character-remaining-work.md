# pixelart-character — remaining-work

할 일만 남기는 파일입니다. 끝난 항목은 여기서 **지우고**, 완료 기록은 change-log가 담습니다.

## 다음 작업 큐

- **기존 시점 자료 대응 확인** — 실제 그림이 화면에서 바라보는 방향으로 side_left·side_right를 판별하고 같은 방향의 3/4·idle·walk와 대조합니다. 이후 저장 시 view/버전 폴더와 새 파일명으로 대응시키고 기존 승인·원본 이력을 보존합니다.

- **사막여우 시안 정리와 방향별 도트 제작** — 기존 turnaround-v3 자료를 보존하고 정면 계열 4면도의 양쪽 측면 및 좌향·우향 3/4 대표 자세를 새 기준으로 대조·보완합니다. 사용자 확인 후 160 작업·320 정면 및 방향별 3/4·idle 준비·walk 준비 그림을 제작합니다.

- **표정 시안 검수** — 기본·웃음·슬픔·화남의 상황·강도·눈썹·눈매·입을 설정에 기록하고 기본과 겹치는 감정도 이름 없이 구별되도록 검수합니다.

- **방향별 동작과 도구 이관** — 해당 방향 정지본 승인과 별도 동작 요청 뒤 idle_left·idle_right·walk_left·walk_right를 제작합니다. 기존 단순 반전 출력은 새 규칙 통과로 보지 않습니다. 등록 시 방향별 파일·동작 식별자와 소비 엔진의 매핑을 확인합니다.

- **sprite-gen idle 시험 검토** — export/ice-queen/sprite-gen-idle-v1/idle-preview.gif와 validation.json을 확인합니다. 얼굴·발 보존은 검사했으며 호흡 강도·목 연결·꼬리 외곽선은 사용자 검토 대기입니다. 공통 idle 4프레임 사양은 유지합니다.
- **입력 기준선 정정** — 기존 320 v2 발바닥 y=301이 현행 사양 y=303과 다릅니다. 정지본의 비율·기준선 검수와 승인 후 배포본에 반영합니다. 보정 방법은 승인됐으며 규칙서 v1.14에 따라 아래 2px을 일괄 적용한 별도 버전을 제작해야 합니다. 기존 v1은 보존합니다.

- **Unreal Engine 검수** — 실제 엔진 버전·대상 플랫폼·프로젝트가 정해지면 R28에 따라 NoMipmaps·Nearest·Never Stream·추가 패딩 없음·밉 1개·화면 크기·기준점·외곽선·시트 번짐을 확인합니다. 현재는 엔진 검수 대기입니다.

- **160·320 규격 적용** — 160 원본·320 얼굴 보정·320 최종 배포를 연결합니다. 기존 생성기·검사기·공통 몸체·동작 offsets의 좌표와 기준점을 확인합니다. 기존 512 시험 생성기는 재사용 전 패딩을 제거하고 방향별 입력·출력을 적용해야 합니다. 사양 기록만으로 도구 이관 완료를 선언하지 않습니다.

- **얼음여왕 후속 검수** — 320 v2의 눈 폭·눈매·입 표현을 유지합니다. 가려진 관절·방향·옷과 손 겹침을 검수하고 새 320 배포본을 준비합니다. 256 v1은 비교 이력, 눈을 넓힌 320 v3는 미채택으로 보존합니다.

- **얼굴 보정의 애니메이션 도구 이관** — 정지 디자인 v2의 얼굴 보정·마스크 검사는 `retouch-face-v2.lua`와 `verify_face_v2.py`에서 처리합니다. 이후 애니메이션 요청 시 `verify_delivery.py`·애니메이션 생성기에 보정 레이어 합성과 프레임별 마스크 밖 RGBA 검사를 적용합니다. 기존 전체 2배 격자 검사를 보정 얼굴에 그대로 강제하지 않습니다.

- **단계별 승인 기록 적용** — 다음 캐릭터 작업은 규칙서 v1.14의 1024×1024 시안 → 별도 승인된 320×320 정지 이미지 → 320×320 배포 검수 → 요청 시 애니메이션 순서로 진행합니다. 기존 채택 외형은 유지하되 게임용 정지 이미지 승인으로 간주하지 않습니다. 단계마다 대상 파일·버전·실제 크기·승인 상태를 기록합니다.

- **얼음여왕 동작 초안 검수** — 착수 조건: 320×320 정지 이미지의 별도 승인과 애니메이션 작업 요청. 기존 초안은 보존합니다. `sprites/ice-queen-v1.aseprite`에서 가려진 옷·관절 보완, 보행 접지와 방향·R01~R30을 확인합니다. `export/ice-queen/validation.json`은 격자·색·타이밍 검사 결과이며 전체 스타일 승인과 다릅니다. 공통 생성기를 다시 돌리면 Aseprite 손질이 덮이므로 별도 버전을 사용합니다.

- **전신 방향·의상 구분 검수** — 이그프리트와 얼음여왕의 다음 수정은 규칙서 v1.14로 얼굴·몸·발의 방향과 옷 중심선을 확인합니다. 얼음여왕의 의상 재설계 시 제복의 색상 변형을 피하고 구조 후보 3개를 비교합니다. 현재 그림을 새 규칙 전체 통과로 처리하지 않습니다.

- **도트 밀도 이관** — 다음 캐릭터 수정은 규칙서 v1.14의 160×160 작업 원본부터 제작합니다. 기존 v4 전신은 이전 밀도의 초안으로 보존합니다. 얼굴·옷을 새 격자에서 정리하고 2배 확대본의 동일 RGBA 2×2px 블록을 확인하고, 얼굴 보정 후에는 마스크 밖 RGBA 일치와 승인 시안의 밀도를 확인합니다.
- **동작 제작 전 도구 이관** — 기존 변환기·공통 몸체·idle/walk 오프셋을 160 작업 격자로 옮기는 방법과 반올림을 결정합니다. 기존 오프셋의 좌표 공간을 확인하고 160 작업·320 그림과 배포에 맞춰 변환합니다. 현재 render_grid는 메타데이터이며 자동 적용·자동 검사 기능은 없습니다.

사용자 요청 캐릭터 **불의 여왕 이그프리트**: 채택 디자인 `source/igfrit/igfrit-approved-design.png`의 단발·군주 제복을 기준으로
160 작업 원본과 투명한 320 출력을 제작하고, 관절·소매 겹침·왕관과 불꽃 범위·팔레트·발 방향을 검수합니다.
320×320 정지 이미지를 별도 승인받고 애니메이션 제작 요청이 있으면 파츠를 분리하고 가려진 부위를 보완합니다. 상세는 `spec/design/characters/igfrit.md`입니다.
이전 v4 좌우 전신은 장발·드레스의 과거 초안이므로 새 제작의 외형 기준으로 사용하지 않습니다.

완성 시 R01~R30으로 검수합니다. 기존 초안은 규칙서를 만들었다는 이유만으로 통과 처리하지 않습니다.

## 사용자 결정 대기

- **사막여우 v3 시안 묶음 확인** — `source/desert-fox/turnaround-v3/`의 두 비교판과 개별 1024 투명 원본을 확인합니다. 대표 정면 v1·3/4 v2는 유지했습니다. 새 필수 자료는 정면 계열 4면도와 좌우 3/4 대표 자세이며 기존 3/4 삼면도는 반복 제작하지 않습니다. 머리천 후면·조끼 등판·꼬리 부착점과 시점별 외형 일치를 확인하면 다음 도트 단계로 진행합니다.

- **얼음여왕 배포본 승인** — 다음 320 배포본 제작 후 실제 파일·버전·검수 결과로 승인을 받습니다. 기존 1024 시안 승인은 유지하며 256 v1을 현행 승인 대상으로 삼지 않습니다.


- **입력 그림 준비** — 6등신 채색 그림을 누가 어떻게 준비하는지(직접 그림 · 외주 · 다른 도구로 생성). 큐 1번 전까지 필요합니다.

- **캐릭터 색** — 입력 그림이 오면 `palette_suggest.py`로 후보를 뽑아 확정합니다(두 사양 함께).
